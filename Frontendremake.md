# AI Playlist Generator — Modern UI Design Scope

## Design Direction

The application should feel like a **premium AI music discovery tool**, combining the atmosphere of a modern streaming service with the precision of a contemporary AI product.

The existing black, beige, burgundy and teal palette remains unchanged. The redesign should not introduce a new visual identity; instead, it should make the existing palette feel more sophisticated, dimensional and intentional.

The interface should feel:

* Modern
* Premium
* Musical without being literal
* Minimal but not empty
* Interactive
* Slightly experimental
* Fast and responsive
* More like a polished product than a poster or concept piece

The visual language should sit somewhere between **Apple Music, Spotify, Linear and modern AI interfaces**, while retaining its own personality.

---

## Color System

The existing palette remains the foundation.

| Token           | Hex       | Usage                                              |
| --------------- | --------- | -------------------------------------------------- |
| `--ink`         | `#0B0B0C` | Main page background                               |
| `--ink-2`       | `#16161A` | Cards, panels and elevated surfaces                |
| `--beige`       | `#E7DFD1` | Primary text                                       |
| `--beige-dim`   | `#C9BFAC` | Secondary text and metadata                        |
| `--burgundy`    | `#7A1F2B` | Primary actions, active states and playback        |
| `--burgundy-lt` | `#9B2F3D` | Hover and active burgundy states                   |
| `--teal`        | `#1E6E78` | Ambient background glow                            |
| `--teal-lt`     | `#2F97A4` | Secondary interaction, focus and subtle highlights |

### Color philosophy

Burgundy represents **action and energy**.

Teal represents **discovery and interaction**.

Beige represents **content**.

Black represents **space and atmosphere**.

The interface should avoid large blocks of saturated color. Burgundy and teal should appear primarily as **accents, gradients, glows, borders and active states**.

# Typography

Continue using the existing font system, but simplify how it is applied.

### Fraunces

Use for:

* Main hero heading
* Generated genre title
* Occasional large musical statements

Fraunces should provide personality rather than dominate the interface.

### Instrument Sans

Use for:

* Buttons
* Navigation
* Form controls
* Track titles
* Descriptions
* UI labels

### JetBrains Mono

Use sparingly for:

* Genre labels
* Track numbers
* Small metadata
* System/status indicators
* Technical details

Avoid using monospace for too much of the interface. It should function as an accent rather than the primary visual language.

# Background

The near-black background remains.

Instead of a static poster-like radial glow, use a **very subtle generative ambient background**.

The background can contain:

* Large blurred teal glow
* Smaller burgundy glow
* Extremely subtle geometric shapes
* Grain/noise texture
* Very slow movement

The movement should be almost imperceptible.

The background must never compete with the content.

A useful visual hierarchy is:

```text
background
   ↓
ambient glow
   ↓
content
   ↓
interactive surfaces
   ↓
primary actions
```

Avoid obvious animated blobs or excessive gradients.

---

# Header

Use a small, minimal header.

Left:

**AI PLAYLIST**

or a compact product mark.

Right:

* About
* How it works

The header should be visually quiet.

Use Instrument Sans for navigation and JetBrains Mono for the small product label.

No large traditional navigation bar is necessary.

---

# Hero

The hero is the primary interaction point.

Replace the old:

> AI PLAYLIST GENERATOR
> Playlist generator

poster composition with a more confident product statement.

Large Fraunces heading:

**Discover your next sound.**

Supporting text:

**Choose a genre and let AI build a ten-track playlist you can actually listen to.**

The hero should have considerable vertical breathing room.

The title can occupy two lines on desktop.

Example:

```text
DISCOVER
YOUR NEXT SOUND.
```

The typography should be large enough to create a strong first impression without feeling like a marketing landing page.

---

# Generator Control

The genre selector and generate button should feel like **one unified interactive component**.

Instead of:

```text
[ Genre dropdown ] [ Generate ]
```

use a connected control:

```text
┌───────────────────────────────────────────────────────┐
│  GENRE                                                │
│  Afrobeats                              Generate →    │
└───────────────────────────────────────────────────────┘
```

The container should use `--ink-2`.

Border:

`rgba(231,223,209,0.10)`

On hover/focus, introduce a subtle teal border/glow.

The Generate action should use burgundy.

On hover:

* Slight elevation
* Burgundy becomes `--burgundy-lt`
* Small horizontal movement of the arrow
* Very subtle glow

The button should feel tactile rather than decorative.

---

# Loading State

The existing glitch concept should be removed as the primary loading animation.

Instead, use a **musical/AI generation state**.

When generation starts:

```text
GENERATING PLAYLIST

Afrobeats
Finding a sequence of tracks...
```

The interface can display a subtle animated waveform or horizontal frequency bars.

The animation should be restrained and elegant.

The page should communicate that something is actively happening without looking like a broken screen.

---

# Status / Error State

Status messages should be integrated into the interface instead of appearing as an isolated line.

For example:

```text
● PLAYLIST GENERATED
```

or:

```text
● USING CURATED BACKUP
The AI service was unavailable, so we've loaded a verified playlist.
```

Use:

* Teal for successful/system states
* Burgundy for fallback/error states

The fallback mechanism should remain visible and honest, since this is an important part of the technical demonstration.

---

# Playlist Result

Once generated, the playlist should become the dominant component.

Introduce the section with:

```text
YOUR PLAYLIST
```

in JetBrains Mono.

Then:

```text
AFROBEATS
10 TRACKS
```

using Fraunces for the genre and Instrument Sans/mono for metadata.

# Playlist Hero Card

Instead of a literal record sleeve, use a **modern playlist identity card**.

The card should use `--ink-2` with a subtle border.

Layout:

```text
┌─────────────────────────────────────────────────────┐
│                                                     │
│  ┌──────────────┐                                   │
│  │              │    AFROBEATS                     │
│  │   ARTWORK    │    AI GENERATED PLAYLIST         │
│  │              │                                   │
│  │              │    10 TRACKS                     │
│  └──────────────┘                                   │
│                                                     │
```

The artwork should be substantially larger than the previous 48px track artwork.

Approximately:

* Desktop: 220–280px
* Mobile: 150–200px

The artwork can use the first returned album image or a generated visual treatment based on the genre.

Do not add a physical vinyl record unless it is used extremely subtly.

The goal is **digital playlist**, not physical record sleeve.

# Track List

The track list should resemble a premium streaming interface.

Each track contains:

```text
01
[ artwork ]
Track title
Artist
                           30s      ▶
```

Use approximately:

* 52–64px artwork
* 16–18px track title
* 12–13px artist metadata
* 12px monospace track number

Rows should have generous vertical padding.

Avoid heavy cards around individual songs.

Instead use extremely subtle separators.

Example:

```text
01   [IMG]   Essence
             Wizkid                         0:30   ▶

────────────────────────────────────────────────────────

02   [IMG]   Calm Down
             Rema                           0:30   ▶
```

This keeps the playlist elegant and easy to scan.

---

# Playback Interaction

The currently playing song should receive a strong but restrained visual state.

For the active track:

* Burgundy play button
* Small burgundy indicator beside the track number
* Track title becomes brighter
* Optional animated waveform replaces the play icon

Example:

```text
03   [IMG]   Last Last
             Burna Boy                     0:30   ❚❚
     ↑
     burgundy active indicator
```

Only one track may play at a time.

When another track is selected, the previous preview stops immediately.

# Play Button

The preview button should be circular.

Default:

* Transparent/`--ink-2`
* Thin beige or teal border

Hover:

* Teal highlight

Playing:

* Burgundy background
* Beige icon

The interaction should have a short transition around 150–200ms.

# Album Artwork

Album artwork should be treated as a major visual element.

Use:

* Rounded corners
* Consistent aspect ratio
* `object-fit: cover`
* Subtle shadow

Avoid excessive rounded cards.

The artwork itself should provide most of the visual variety in the playlist.

If artwork is unavailable, use a sophisticated fallback:

```text
GENRE
AFROBEATS
```

with a subtle burgundy/teal gradient and noise texture.

# Apple Music Interaction

Artist names should remain clickable.

Normal:

`Wizkid`

Hover:

* Beige becomes teal-lt
* Subtle underline

The external Apple Music link should feel like a natural part of the track metadata rather than an obvious external-link button.

# Generate Interaction

The Generate button should have a subtle physical response.

On hover:

* Translate approximately 1–2px
* Slight burgundy glow
* Arrow moves 2–3px

On click:

* Compress slightly
* Return smoothly

Do not use exaggerated cursor-following effects.

The interaction should feel premium, not gimmicky.

---

# Micro-interactions

Use animation primarily to communicate state.

### Page load

Hero elements fade/translate upward slightly.

### Generation

Generator enters loading state.

### Playlist appearance

Playlist container fades upward into position.

Track rows can stagger very slightly, approximately 30–50ms each.

### Playback

Active waveform animates subtly.

### Hover

Buttons, links and interactive surfaces respond quickly.

Animation should generally remain between **150–500ms**.

Avoid large cinematic animations.

* Visible focus states
* Proper button semantics
* `aria-live` for generation/status updates
* Accessible audio controls
* Sufficient contrast
* Reduced-motion support

When `prefers-reduced-motion` is enabled, disable ambient movement and staggered animations.

# Vue Bits Animation System

Animation should be treated as part of the product's interaction design, not as decoration layered on top of the interface. The project should use **Vue Bits** selectively for high-value moments such as the ambient background, hero entrance, playlist reveal and generation state. Vue Bits provides animated Vue components and backgrounds designed to be customized through props, making it appropriate for the Vue 3 frontend.

The implementation should favor a small number of carefully chosen effects over using many animated components at once. The finished product should feel alive, but never like a component-library showcase.

## Recommended Vue Bits Components

### 1. Aurora / ColorBends — Ambient Background

Use **Aurora or ColorBends** as the primary hero/background animation.

It should sit behind the entire hero and extend subtly into the playlist transition area. The component should be customized to the existing palette rather than using its default neon colors:

* Teal: `#1E6E78`
* Teal light: `#2F97A4`
* Burgundy: `#7A1F2B`
* Burgundy light: `#9B2F3D`

The effect should have low intensity, slow movement and substantial blur/fade. It should read as **ambient light**, not an obvious animated wallpaper.

The content layer must remain completely independent of the background component so that animation failure cannot affect playlist generation or playback.

Vue Bits currently provides both ColorBends and Aurora-style animated backgrounds.

### 2. Text Animation — Hero Entrance

Use a restrained Vue Bits text animation for the hero heading or eyebrow rather than animating every line.

Recommended behavior:

```text
AI PLAYLIST

Discover
your next sound.
```

The eyebrow can appear first, followed by the main Fraunces heading with a subtle reveal. The animation should complete quickly and then stop.

Avoid perpetual text animation in the hero.

Vue Bits includes dedicated text-animation components such as Text Type and Count Up.

### 3. Gradual Blur — Playlist Reveal

When a playlist is generated, reveal the result using a combination of Vue's native transition system and a restrained **Gradual Blur** effect.

The playlist should feel as though it is resolving into focus:

1. Playlist container fades in.
2. Slight upward movement.
3. Artwork resolves from subtle blur to sharp focus.
4. Track rows enter with a small stagger.

The blur should never make text difficult to read for an extended period. Keep the effect short and controlled.

Vue Bits provides a dedicated Gradual Blur animation component.

### 4. Track List — Native Vue TransitionGroup

Do **not** use a heavy Vue Bits animation for every track row.

Use Vue's native `<TransitionGroup>` for the ten-track playlist. This keeps the list lightweight and gives the application precise control over entering, leaving and reordering tracks. Vue's TransitionGroup supports keyed list movement animations using CSS transforms.

Each row should enter with:

* opacity: `0 → 1`
* translateY: `8px → 0`
* optional blur: `4px → 0`
* stagger: approximately `35–45ms`

The animation should stop once the list has appeared.

### 5. Generation State — Animated Visualizer

During playlist generation, use a small animated waveform/frequency visual rather than the previous glitch effect.

The visualizer should use the teal and burgundy accents and communicate that the application is actively constructing the playlist.

Example state:

```text
GENERATING PLAYLIST

AFROBEATS

▂ ▅ ▃ ▇ ▄ ▆ ▂

Finding a sequence of tracks...
```

The waveform should animate continuously only while the request is pending. Once the API returns, the animation stops and transitions into the generated playlist.

This creates a direct visual relationship between **AI generation** and **music playback** without pretending that the waveform represents real audio.

---

# Animation Architecture

Animation must never be coupled to application logic.

The architecture should remain:

```text
API state
   ↓
Vue application state
   ↓
UI state
   ↓
animation components
```

Not:

```text
animation
   ↓
API logic
```

The playlist should remain fully functional if an animation component is removed or fails to render.

Vue Bits components should therefore be isolated into dedicated visual components such as:

```text
components/
  visual/
    AmbientBackground.vue
    HeroReveal.vue
    GenerationVisualizer.vue
    PlaylistReveal.vue
```

The application components should consume these visual components rather than importing Vue Bits directly throughout the application.

This preserves the project's existing separation-of-concerns philosophy.

---

# Animation Timing

Use a consistent timing system:

| Interaction           |                 Duration |
| --------------------- | -----------------------: |
| Button hover          |                150–200ms |
| Button press          |                100–150ms |
| Text reveal           |                500–800ms |
| Playlist reveal       |                500–700ms |
| Track stagger         |                  35–45ms |
| Artwork blur reveal   |                450–650ms |
| Ambient background    |    Continuous, very slow |
| Generation visualizer | Continuous while loading |

Use spring-like easing for physical interactions and smooth ease-out curves for content reveals.

Avoid excessive bounce, elastic motion or large-scale transforms.

---

# Cursor Interaction

Vue Bits cursor effects should only be considered if they materially improve the experience.

A subtle magnetic interaction on the Generate button is appropriate because it reinforces the primary action.

The effect should:

* Respond only within a small radius
* Move the button by a few pixels
* Return smoothly when the cursor leaves
* Never move surrounding layout
* Be disabled on touch devices

Do not add a global custom cursor simply because the library supports one. The standard cursor should remain available for accessibility and familiarity.

---

# Scroll / Section Transition

If the playlist extends below the fold, the transition from hero to results can use a subtle reveal rather than a dramatic scroll animation.

The playlist section should begin slightly below its final position and resolve as it enters the viewport.

No parallax-heavy effects should be used.

The music content is more important than the animation.

---

# Motion Hierarchy

Animation should follow the same hierarchy as the visual design:

**Ambient**

Slow Aurora/ColorBends background.

**Expressive**

Hero text reveal and playlist reveal.

**Functional**

Generation visualizer and playback state.

**Micro**

Button hover, play button, links and focus states.

Nothing should compete with the current action.

---

# Reduced Motion

All animation must respect `prefers-reduced-motion: reduce`.

When reduced motion is enabled:

* Disable animated backgrounds or reduce them to a static gradient.
* Disable text animation.
* Remove track staggering.
* Remove magnetic cursor behavior.
* Replace large transitions with simple opacity changes.
* Keep functional playback indicators understandable without animation.

Accessibility takes priority over visual effects.

---

# Performance Rules

Vue Bits components should be used only where their visual value justifies their runtime cost.

In particular:

* Do not mount multiple WebGL-heavy backgrounds simultaneously.
* Do not render animated components for every track.
* Do not continuously animate hidden playlist elements.
* Pause or remove expensive background effects when they are not visible.
* Lazy-load non-critical visual components where practical.
* Keep API and audio playback independent of animation lifecycle.

The page should remain responsive on ordinary laptops and mobile devices.

---

# Professional Animation Rule

The goal is **not to make the website look animated**.

The goal is to make the interface feel **responsive, alive and intentional**.

If a visitor notices the animation before they notice the music, the animation is too strong.

The ideal experience is:

> The background breathes. The typography arrives. The generator responds. The playlist resolves. The active track moves subtly.

Everything else stays out of the way.
